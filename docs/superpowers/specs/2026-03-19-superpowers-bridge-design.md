# Superpowers Bridge — CLAUDE.md + SPEC.md Generation

**Date:** 2026-03-19
**Status:** Approved
**Affects:** gw:research, gw:saas-idea

## Overview

Add CLAUDE.md and SPEC.md generation to gw:research and gw:saas-idea at the implementation decision points. These files bridge gw-skills output into the superpowers workflow, enabling `superpowers:writing-plans` to create implementation plans directly from the research/saas-idea artifacts.

## Superpowers Invocation

When the user chooses [p] (Superpowers), the orchestrator invokes the Skill tool:

```
Skill(skill="superpowers:writing-plans")
```

Superpowers is a Claude Code plugin installed at `~/.claude/plugins/`. The Skill tool is the correct invocation mechanism — it loads the skill content and the orchestrator follows the loaded instructions. The writing-plans skill will read CLAUDE.md for project context and SPEC.md for requirements, then produce an implementation plan.

The orchestrator tells the user before invoking:
```
CLAUDE.md and SPEC.md generated. Invoking superpowers:writing-plans to create an implementation plan.

The plan will use:
  - CLAUDE.md for project context, tech stack, and constraints
  - SPEC.md for requirements and success criteria
```

## Section Skipping Logic

For gw:research, sections are skipped when the research domain doesn't produce relevant data:

| Section | Include when |
|---------|-------------|
| User Flows | Research domain is engineering, design, or business with user-facing output |
| Data Model | Consensus recommendations imply data structures |
| API Design | Consensus recommendations imply interfaces |
| Implementation Phases | Always omit — superpowers:writing-plans will create these |

For gw:saas-idea, all sections are always populated since the deep-dive artifacts cover everything.

## File Copy Logic

After generating in the output directory:

**For CLAUDE.md:**
1. Check if `CLAUDE.md` exists at project root
2. If it does, ask: "CLAUDE.md already exists at project root. Overwrite [o], merge [m], or keep output-dir copy only [k]?"
   - **Overwrite:** replace entirely with generated version
   - **Merge:** append a `## Generated by gw:{skill}` section to the existing file, preserving the user's original content above
   - **Keep:** don't copy, just tell the user: "Generated CLAUDE.md available at {output_dir}/CLAUDE.md"
3. If it doesn't exist, copy directly

**For SPEC.md:**
1. Check if `SPEC.md` exists at project root
2. If it does, ask: "SPEC.md already exists at project root. Overwrite [o], or keep output-dir copy only [k]?"
   - **Overwrite:** replace entirely with generated version
   - **Keep:** don't copy, just reference the output directory path
   - Note: no merge option for SPEC.md — merging two requirement specs would create duplicate/conflicting requirements. Overwrite or keep separate.
3. If it doesn't exist, copy directly

## File Listing Update

Both skills have a "Present Results" or "File Listing" step near the end. When CLAUDE.md and SPEC.md were generated, include them in the artifact listing:
```
  {output_dir}/CLAUDE.md              ({N} lines)
  {output_dir}/SPEC.md                ({N} lines)
  ./CLAUDE.md                         (copied to project root)
  ./SPEC.md                           (copied to project root)
```

## Error Handling

- If CONSENSUS.md doesn't exist (research) or deep-dive artifacts are missing (saas-idea): "Cannot generate project files — required artifacts are missing. Run the full skill first."
- If file copy fails (permissions): generate in output directory only, tell user the path
- If superpowers:writing-plans is not available: "superpowers:writing-plans not found. The files are ready at {paths} — invoke the skill manually when available."
