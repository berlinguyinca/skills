Three approaches to making the weekly deck hit harder

Each addresses the "GitHub dump" problem differently. Click the one that resonates most.

A

Narrative Rewrite — Fix the Story, Keep the Structure

What changes: Better narrative synthesis by Claude. Instead of listing PRs, Claude identifies 2-3 "themes of the week" and writes the deck around those themes. PRs become supporting evidence, not the skeleton. KPIs become outcome-oriented ("30-min auto-recovery" not "7 new capabilities"). Remove the Q&A step — Claude figures it out.

What stays: Same slide count, same python-pptx renderer, same visual system. The chart types stay but get smarter captions.

Trade-off: Fastest to implement. Biggest bang for buck. But the slides still look the same — just say better things.

B

Visual Overhaul — Redesign the Slide Templates

What changes: New slide layouts with better information density. Replace generic bar/donut charts with purpose-built visuals: timeline strips, before/after callouts, impact magnitude indicators. KPI cards get visual weight (large numbers, small labels). Remove redundant slides (merge "Key Deliverables" + "Impact Details" into one). Better use of whitespace and visual hierarchy.

What stays: Same data pipeline, same GitHub queries, same categorization logic.

Trade-off: Slides look dramatically better. But if the narrative is still PR-driven, pretty slides with shallow content just look better while saying the same thing.

C

Full Rethink — Narrative + Visuals Together

What changes: Both A and B. Claude synthesizes top-down themes from PRs, then the renderer uses layouts designed for those themes. A "theme slide" gets a headline + 2-3 evidence bullets + a visual anchor (metric callout, timeline, or before/after). Strict 4-5 slide max: Title → Week's Headline → 2-3 Theme Slides → What's Next. Every slide has one job. Remove Q&A, remove redundant slides, remove vanity charts.

What stays: Same GitHub data pipeline, same config system, same uv/python-pptx toolchain.

Trade-off: Most work. But this is the version where someone glances at the deck and thinks "wow, they shipped a lot this week" — which is the whole point.

My recommendation: C. The problem is that content and visuals are both weak — fixing one without the other just moves the bottleneck. And with a strict 4-5 slide limit, each slide has to nail both story and presentation. The data pipeline is solid — it's the synthesis and rendering that need the rethink.
